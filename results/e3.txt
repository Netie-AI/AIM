==============================================================================
E3.1  facts held in a fixed state, at >=90% recall
      value dim=64, value pool=2048, 3 trials/point
==============================================================================
   d_k   state (KB,fp16)   hebbian   per d_k     delta   per d_k
    32               4.0        73      2.28        26      0.81
    64               8.0       152      2.38        64      1.00
   128              16.0       302      2.36       123      0.96
   256              32.0       622      2.43       264      1.03

  Both rules are linear in d_k, but they are linear for different
  reasons. The delta rule saturates at almost exactly 1.0 pairs per
  d_k: it is solving least squares, so once keys stop being linearly
  independent, new writes overwrite old ones. Plain outer-product
  writes never overwrite, they only accumulate crosstalk, and under a
  discrete readout that buys ~2.4x more capacity at the price of
  exactness. Exact-but-capped vs approximate-but-graceful is a real
  design choice, not a strict ordering.

==============================================================================
E3.2  bytes per fact: fixed state vs an exact KV cache
==============================================================================
   d_k   hebbian B/fact   delta B/fact   KV cache B/fact  hebbian vs KV
    32               56            158               192           3.4x
    64               54            128               256           4.8x
   128               54            133               384           7.1x
   256               53            124               640          12.1x

  Cost per fact in the recurrent state is flat at ~54 B and does
  not depend on d_k, because both state size and capacity are linear
  in d_k. A KV cache costs 2*(d_k + d_v) B per fact and gets worse as
  the model widens. So the fixed state is not merely bounded, it is
  cheaper per fact -- but at 90% recall, not exact recall. That is the
  actual trade being made, and it is the one to defend.

==============================================================================
E3.3  extrapolation to a real memory budget
==============================================================================
      8,192 items   KV cache (8B-class, GQA):     1.0 GB   |  recurrent state:     0.4 MB   (  2417x)
    131,072 items   KV cache (8B-class, GQA):    16.0 GB   |  recurrent state:     6.8 MB   (  2417x)
  1,000,000 items   KV cache (8B-class, GQA):   122.1 GB   |  recurrent state:    51.7 MB   (  2417x)

  Assumption stated plainly: this treats every context item as one
  retrievable fact, which overstates what a real context holds. Even
  discounted by 10x, the state fits in on-die SRAM while the KV cache
  does not fit anywhere but HBM. That gap is the whole hardware
  argument, and it is the part of the original plan that survives
  contact with numbers intact.
